# 晶圆缺陷坐标复查

用第一道工序（基准图）的晶粒网格，为同一片晶圆上各道工序留下的缺陷换算统一坐标。
网页上传最多 6 道工序的 CSV，SQLite 保存原始记录与**配准约束**；定位点补点/更正/
撤去后，约束在同一事务里增量维护，所有受影响工序的查询结果一并重算；无解或保存
失败时整套改动回滚，沿用此前生效的定位点与约束。

## 快速启动

```bash
docker compose up --build -d
# 打开 http://127.0.0.1:8000
```

首次打开可点“新建复查 → 一键填入演示数据”，或从“新建复查”页下载 `samples/`
里同名的 6 个 CSV 再上传。数据保存在 Docker 卷 `wafer-data` 里，删除容器不会丢。

本机不装 Docker 时：

```bash
python3 -m pip install -r requirements.txt
WAFER_DB=data/wafer_review.sqlite3 gunicorn --bind 0.0.0.0:8000 wsgi:app
```

## CSV 格式

每行一个定位点或缺陷，字段为“类型, 编号, 行, 列”，行列从 1 起算：

```csv
类型,编号,行,列
定位点,L1,2,7
定位点,L2,2,6
缺陷,D101,4,4
```

* 类型可写“定位点 / 缺陷”，也接受 `locator / defect`、`L / D`；
* 表头可有可无，中英文表头均可，列顺序按表头识别；
* 同一个**定位点编号**在不同工序里代表同一枚物理标记，这就是对齐的依据；
* 基准图没有的定位点编号，只要在多道工序之间同号，也参与约束（见下文）。

示例数据在 `samples/`，可用 `python scripts/gen_samples.py` 重新生成。

## 对齐模型

每道工序可独立选择以下 8 种变换之一（基准图固定为“原样”）：

| 变换 | 说明 |
| --- | --- |
| 原样 / 顺时针90° / 旋转180° / 顺时针270° | 纯旋转 |
| 左右镜像 / 镜像+顺时针90° / 镜像+旋转180° / 镜像+顺时针270° | 镜像或镜像叠加旋转 |

一个**方案**是“每道工序各选一个变换”。约束是：所有同号定位点换算到基准坐标系后
落在同一格；若基准图里也有该编号，这个格子还必须正是基准图上的位置。

* 不同工序可能通过“基准图没有的同号定位点”互相牵制，所以枚举的是**全局方案**
  （最多 8⁵ = 32768 种组合，实测约 0.2 秒）；
* 查询“工序 + 缺陷号”时，收集该缺陷在**所有可行方案**下的落点：
  * 都落在同一格 → 给出基准坐标；
  * 落在不同格 → 标为**待定**，并列出候选格；
  * 不存在任何可行方案 → 无解（正常保存流程不会留下这种状态）。

### 配准约束的持久化（位图）

约束按**工序对 × 同号定位点编号**存成最小片段（表 `pair_constraint`）：

* 一道工序有 8 种变换，一对工序就是 8×8 = 64 种“变换搭配”。一个同号点允许哪些
  搭配，记成一个 64 位位图（位 `k*8+m` 为 1 表示分别取第 k、m 号变换时该同号点
  换算后重合）；
* 一对工序的**有效约束 = 该对所有同号点位图的按位与**。因此撤去一个同号点只需
  删除它自己的片段，原先被它排除的变换搭配，**只有在别的同号点也允许时才恢复**；
* 补点/改点/撤点时只从定位点明细读取**本次涉及编号**的记录，重建这些编号的片段，
  不扫描其它编号；校验与查坐标都直接枚举已维护的约束，不再逐个比对同号点；
* 约束与定位点在**同一个 SQLite 事务**里提交，一次查询读到的必定是同一次提交的
  状态。表 `constraint_meta` 记录约束随哪一版定位点建好；旧库首次使用（应用启动
  或第一次写操作）时按当前定位点自动补建。

查询结果不落库，每次由已提交的定位点与约束即时推导，因此定位点、约束与结果天然
同步。

## 更正、补点与撤点

* 每个定位点都可改行列、补同号点或整体撤去；
* 写操作和随后的可行性校验在**同一个 SQLite 事务**里完成：先更新定位点，再增量
  重建涉及编号的约束片段，然后用新约束枚举整片晶圆的全局方案。校验不通过就整体
  回滚，原定位点、原约束、原查询结果保持不变，页面给出“未生效”提示；
* 改动成功后，所有工序的查询结果立即按新约束重新推导，不需要重新上传。

## 演示脚本

`samples/6_封装.csv` 只有 C1 一个定位点，而基准图没有 C1——它靠与“沉积”共享
C1 才能对齐。因此：

| 操作 | 结果 |
| --- | --- |
| 初始状态 | 可行方案 2 套；封装 D101/D103/D105 有坐标，D102/D104 待定 |
| 撤去“沉积”的 C1（连续撤点①） | C1 约束片段整体消失，可行方案变 8 套，封装全部缺陷变待定 |
| 再撤去“光刻”的 L1（连续撤点②） | 含光刻的 L1 片段消失，L1 仍在其余工序对之间生效；仍 8 套方案 |
| 撤点中途查 D103/D101 | 页面给出“待定”，方案数与坐标判定来自同一次提交的状态 |
| 补回后把封装 C1 更正到 (4,4) | D104 由待定变确定 (5,5)（演示“更正后结果更新”） |
| 把封装 C1 改成 (1,1) | 无可行方案，操作被拒绝，定位点、约束与结果保持原样 |

网页上的“全部工序叠加到基准坐标系”图，用每道工序的第一个可行变换把定位点和缺陷
画到同一张网格上，便于肉眼核对。复查页的“配准约束”面板逐工序对列出同号点片段、
每个片段允许的变换搭配数（/64）以及按位与后的有效位图。

## 架构

```
wafer_review/
├── app.py         Flask 应用工厂与路由
├── geometry.py    8 种 D4 变换、逆变换与变换编号
├── csvparse.py    CSV 解析与校验
├── db.py          SQLite schema（wafer / step / locator / defect
│                  / pair_constraint / constraint_meta）
├── constraints.py 配准约束位图的落库、增量维护与旧库补建
├── model.py       位图推导、基于约束的全局方案枚举、逐缺陷查询
├── service.py     上传、补点、更正、撤去（事务 + 回滚）
├── overlay.py     多工序叠加视图
├── gridview.py    网格渲染数据
├── demo.py        演示数据定义（CSV 与 samples/ 同源）
└── templates/ static/
```

约束相关接口：`GET /api/wafers/<id>/constraints` 返回逐工序对的同号点片段、
各片段允许的搭配数与按位与后的有效位图；复查页“配准约束”面板展示同样的信息。

## 限制

* 每边格数可设为 2–60（默认 8），但变换只覆盖**正方形**网格的对称操作；非正方形
  的晶粒排布不支持；
* 不解析缺陷明细图/坐标文件，只认 CSV；
* 认证与多用户隔离未实现，定位点操作对所有访问者开放——仅适合内网质检工具场景。
